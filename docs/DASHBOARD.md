# The public telemetry dashboard

*Owned by EPIC-04. The permanent artifact, and the source of the book's figure.*

---

## The permanent URL

> **https://controllabilitydev.github.io/mist/**

**This URL is a stability commitment.** It is quoted in the book, and a book
cannot be re-published because a link moved. It will not change for
reorganisation, rebranding, or a nicer domain. If the project is ever archived,
the last build stays at this address.

The page is **static** — no server, no runtime data fetch. It renders correctly
from an archive years from now with the deployment long gone. That is a
requirement, not a side effect: a dashboard that needs a live backend to explain
a book figure is a dead figure.

## What the page says, and why it says it that way

### The framing block

> **THIS IS A BILL, NOT A RETURN VALUE.**

Without that sentence the page reads as an ordinary security dashboard and the
argument is invisible. It is the line that makes a screenshot self-explanatory
when it appears in print without its surrounding chapter.

It states counter-invariant `CI-2` (`docs/ANTI_KERNEL.md`): in a controllable
system, telemetry is the return value of the transition function. Here it is an
invoice from external tooling, purchased after the fact, because the inputs were
never controlled.

### Current state

Seven metrics with their change since the previous run. **Red** means findings
were reported *or* a scanner crashed — a crashed scanner is not a clean one, and
showing it as green would be the false-green failure the whole envelope design
exists to prevent.

Skipped scanners are listed separately. **A skipped scanner reports nothing,
which is not the same as reporting zero.**

### The split that matters

Second-party findings beside first-party ones. Mist's claim is that its defects
arrive in `node_modules` and no code review would catch them
(`docs/mist-concept-evaluation.md:68`). That claim is only falsifiable if the
first-party count is shown honestly next to it, so it is.

### Surface growth

What each convenience cost, charted over the record. A rising line is the price
of a feature that was easy to add.

The `network at import` series is labelled **upper bound** on the page, because
it is one — see `docs/SCANNERS.md`. A ceiling charted as though it were a
measurement would be the dashboard lying quietly.

### Findings by counter-invariant

Each finding joined back to the invariant it inverts, `CI-1`..`CI-6`, plus
`unmapped`. **`unmapped` is not a gap in the data.** Some finding types are
genuine hazards that are not inversions of a controllability invariant —
obfuscated source, licence obligations, secrets in history. Forcing them into a
`CI-*` row would inflate a number.

### The 🔒 panels

Decay (EPIC-07) and the Mist Index (EPIC-06) render as visible, labelled
placeholders naming their owning EPIC. A dashboard that silently omitted a panel
it cannot fill would be claiming completeness it does not have.

## What the page will never have

No severity filter. No acknowledge control. No snooze. No won't-fix state.

**If a dashboard can be made to look better without the exposure changing, it is
not an instrument.** `scripts/check-dashboard.mjs` enforces this by asserting the
page contains no interactive controls at all — a stronger claim than "no snooze
button", and a much easier one to verify.

## The record

Scan runs live on the **`telemetry` orphan branch**, not on `main`:

```
telemetry/
  runs/<ts>_<sha>.json     the EPIC-03 envelope, verbatim
  index.json               append-only manifest
```

An orphan branch keeps the record permanent and the specimen clean — scan output
on `main` would churn its history on every push and pollute the SBOM diff
EPIC-03 computes against it.

**The record is append-only.** A run that was red stays red, including runs that
were red because of a Mist bug. `dash-append-only` fails CI if an existing entry
changes or disappears.

**Nothing is backfilled.** The record starts when it starts. The start date is
whatever `index.json` says, and it is shown on the page.

## The instrument is not made of the specimen

`site/` has **zero** npm dependencies: plain HTML, hand-written CSS, and inline
SVG generated by one Node script using only the standard library.

This is the sharpest design decision in the EPIC. An instrument built out of the
thing it measures cannot be trusted twice over: its own supply chain becomes a
confound in every reading, and a compromise of the instrument corrupts the record
it exists to preserve. **A thermometer is not made of fever.**

The exemption is recorded in `CONTRIBUTING.md` so it is a stated rule rather than
an inconsistency a reader has to notice and forgive. The contrast is also the
thesis in miniature, and it is free evidence: **the one part of this repository
built kernel-style needs no scanner.** Nothing in the scan battery has anything
to say about `site/`.

## Building it

```bash
node site/build.mjs --telemetry ./telemetry --out ./site/dist
node scripts/check-dashboard.mjs
node scripts/test-dashboard.mjs
```

Against the synthetic fixture record, for development:

```bash
node site/build.mjs --telemetry ./fixtures/telemetry --out /tmp/dash
```

The fixture numbers are invented and labelled as such in
`fixtures/telemetry/README.md`. Do not quote them.

## Status

**The page is built and verified locally. It is not yet published**, because
GitHub Pages has to be enabled on the repository by a human with admin rights.
`.github/workflows/publish-telemetry.yml` is written and will publish on the
first successful `assemble` once Pages is turned on.

Until then the URL above is a commitment, not a live link, and this document
says so rather than implying otherwise.
